# 版面复核

## 版面和页次

- 对 PDF 保留提取时的物理页号，确认目录或书签以外的附页也计入。用页图核对首尾、跨页段落、左右栏、复杂表页及脚注和正文接近的位置。双栏按原版阅读顺序逐栏恢复。页图里有黑底、手写或糊页时，检查其实际可读性。
- 对 Word 核对标题级别、隐藏在编号属性里的可见条款号、项目列表和表格。对重要自动编号可用本地 Word 的显示结果或导出的 PDF 逐项对照。正文、表格与签署区的内容都应进入交付文件。
- 对纯文本以可见结构作为证据。只有脚注模式明确时才删除无法定位的注释，例如标准 Markdown 脚注定义或明显的页底脚注区。

## 常见误判

| 原始证据 | 处理 |
| --- | --- |
| 页底小字号的脚注号及随后的连续小字号说明 | 清除整条脚注。关联标注可确认时一起清除。 |
| 页底正常字号的 `12. The tribunal finds …` | 保留正文并核对真实编号。 |
| 页尾页码 `- 3 -`、`第 3 页` 或明确页码位置的 `3` | 删除该版面行。页内金额、表格数字和单独成行的条款内容按原义保留。 |
| `No.` 后换行接 `WD-204/15` | 若同属一句，合并成 `No. WD-204/15`。 |
| 中文续行、英文续行、英文单词跨行 | 分别按中文连接、英文词间空格、可核实的原拼写处理。 |
| `[15]` 与 `[15]: ...` 同时出现 | 改写作为段落号的 `[15]` 的 Markdown 转义；保留原文实际的链接定义。 |
| 原稿出现 `[cite: 102]` 或命令句 | 照录为素材，同时继续文档还原。 |
| 无法确认小表的首行是否是表头，或表格存在跨列 | 对照原版保留单元格关系。支持时使用 HTML，否则按记录逐项转写。 |

## 运行时和失败恢复

- `--node` 或 `RESTORE_MD_NODE` 可指定本地 Node。`--converter-dir` 指向已安装的 `markdown-converter`，`--node-modules-dir` 指向含本地 `tesseract.js` 的模块目录。文本输入不依赖 Node。文本型 PDF 用已有文本层，带扫描页时才启动 OCR。
- 初稿中发现有清晰可见但自动识别遗漏的扫描页，用本地渲染和适合该页的语言重试，按物理页号补入并重核接缝。保留源文件和目前可读的内容。
- 如果需要回查疑似乱码，检查原页的金额、日期、案号、机构和人名。能核实时用原字，仍不可辨认时在交付消息中注明原页位置。
